## About DevField

**DevField**는 개발자가 자신의 기술적 이해도와 실무 문제 해결 능력을
실전과 유사한 환경에서 훈련하고 검증할 수 있도록 설계하는
**MSA 기반 개발자 역량 강화 플랫폼**입니다.

GitHub 프로젝트 기반 AI 기술면접 서비스를 시작으로,
코딩테스트와 실무 장애 대응 훈련 등 다양한 서비스를
단계적으로 확장하는 것을 목표로 합니다.

단순한 지식 암기보다 **기술을 이해하고, 직접 문제를 해결하며,
자신의 선택과 구현을 설명할 수 있는 역량**에 집중합니다.

## Our Services

DevField는 각 서비스를 독립적으로 개발하고 운영하며,
사용자가 필요한 훈련을 자유롭게 선택할 수 있는 플랫폼을 지향합니다.

### 01. AI Technical Interview

> **현재 우선 개발 대상**

GitHub 프로젝트를 기반으로 실제 개발 경험과
기술적 의사결정 능력을 검증하는 AI 기술면접 서비스입니다.

**주요 기능 목표**

- GitHub 저장소 등록 및 프로젝트 분석
- 소스 코드와 프로젝트 문서 기반 기술 질문 생성
- AI 면접관과의 모의 기술면접 및 꼬리질문
- 답변의 기술적 정확성과 설명 능력 평가
- 맞춤형 피드백 및 면접 이력 관리

### 02. Coding Test

> **향후 확장 예정**

알고리즘과 자료구조를 중심으로 개발자의
코딩 문제 해결 능력을 훈련하는 서비스입니다.

**주요 기능 목표**

- 알고리즘 및 자료구조 문제 제공
- 코드 작성 및 제출
- 자동 채점 및 실행 결과 확인
- 문제 풀이 기록 관리

### 03. IncidentRoom

> **향후 확장 예정**

실제 운영 환경과 유사한 장애 상황을 경험하고,
문제의 원인을 분석하여 대응하는 실무형 훈련 서비스입니다.

**주요 기능 목표**

- 가상 시스템 장애 시나리오 제공
- 로그 및 메트릭 기반 장애 분석
- 장애 원인 파악 및 대응 절차 수행
- 문제 해결 과정 평가 및 피드백

## Architecture & Engineering

DevField는 **Microservices Architecture(MSA)**와
**Multi-Repository** 구조를 기반으로 설계합니다.

### Core Principles

- **Service Independence**
  - 서비스별 명확한 책임과 독립적인 기능 제공
- **Independent Deployment**
  - 서비스별 독립적인 빌드, 테스트 및 배포
- **Data Ownership**
  - 각 서비스의 데이터 소유권과 접근 경계 분리
- **API-Driven Communication**
  - 명시적인 API 계약을 기반으로 서비스 간 통신
- **Scalability**
  - 새로운 서비스를 기존 기능과 독립적으로 확장
- **Observability**
  - 서비스 운영 상태와 장애를 추적할 수 있는 구조 지향

각 서비스는 독립적으로 이용할 수 있도록 설계하며,
공통 플랫폼을 통해 일관된 사용자 경험을 제공하는 것을 목표로 합니다.

구체적인 기술 스택과 인프라 구성은
요구사항 및 아키텍처 설계 과정에서 확정합니다.
